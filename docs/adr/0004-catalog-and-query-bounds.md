# 0004: Catalog and query bounds

Catalog downloads stop above 8 MiB. Downloads size their buffer from the declared `content-length`, or start at 1 MiB without one, double it when a chunk does not fit and never exceed 8 MiB; they return a view over the received bytes. A buffer always sized at the limit cost that much memory per sync for a catalog of about 5.6 MB. The measured peak heap of downloading, decoding, parsing and normalizing a catalog is about 3.9 times its bytes: 21.1 MiB for the 5.33 MiB live catalog, 30.9 MiB for a 7.99 MiB catalog and 60.4 MiB for a 15.96 MiB catalog. The 8 MiB limit keeps the peak at or below 32 MiB, half of Convex's 64 MiB action memory. Indexed strings fit in 1 KiB of UTF-8; other retained strings fit in 16 KiB, collections have at most 128 entries, normalized model rows fit in 4 KiB and normalized provider rows in 64 KiB of serialized JSON; ADR 0003 derives the cheapest scan bound from the model row limit. Upserts contain at most 100 rows or 512 KiB of serialized JSON. These limits leave headroom for generated fields, price history and mutation serialization.

Catalog mutations clear ETag and body hash while renewing the lease. Writes and the finish are fenced by run ID only: an expired lease that no other run has taken still accepts its run's writes and finish, because rejecting them would discard a nearly complete sync while no competing run exists. Completed data syncs restore `sourceUrl`, ETag and hash together; failures after writes cannot reuse validators from an earlier catalog. Removal uses the stored keys read before upserts. Before catalog writes, an unforced run that would make more than 20% of stored priced models unpriced finishes as partial with `partialReason: "price_loss"` without changing catalog rows. A run whose removal guard skips deletion finishes as partial with `partialReason: "removal"`. A partial run records its counters, which count the loaded catalog, and preserves the last completed timestamp. Malformed providers and models preserve their stored rows. Usable-provider and usable-model floors still apply; these floors also bound repeated removal across runs. Failed source attempts remain ordered fixed-message diagnostics, including when fallback succeeds.

List pages require 1–100 items, read at most `numItems + 1` rows and target at most 1 MiB of document bytes. A document can reach or cross the byte target. Pinned intervals interrupted by those bounds return split metadata. Equivalent-model queries sort priced rows before unpriced rows, then by the required `costOrder` field in descending order. `costOrder` is negated blended price for priced rows and zero for unpriced rows.
