# 0004: Catalog and query bounds

Catalog downloads stop above 8 MiB. Requests do not follow redirects, so the configured HTTPS source is the only origin read. Downloads reject a declared `content-length` above the limit before reading, then decode the stream with a fatal UTF-8 decoder and stop once the streamed bytes exceed the limit; no byte buffer of the whole catalog exists. The measured peak heap of streaming, decoding, hashing, parsing and normalizing a catalog is about 3.8 times its bytes: 20.6 MiB for the 5.33 MiB live catalog, 30.4 MiB for a 7.99 MiB catalog and 59.9 MiB for a 15.96 MiB catalog. The peak is the decoded text plus its parsed value. The 8 MiB limit keeps the peak at or below 32 MiB, half of Convex's 64 MiB action memory. Indexed strings fit in 1 KiB of UTF-8; other retained strings fit in 16 KiB, collections have at most 128 entries, normalized model rows fit in 4 KiB and normalized provider rows in 64 KiB of serialized JSON; ADR 0003 derives the cheapest scan bound from the model row limit. Upserts contain at most 100 rows or 512 KiB of serialized JSON. These limits leave headroom for generated fields, price history and mutation serialization.

Catalog mutations clear ETag and body hash while renewing the lease. Writes and the finish are fenced by run ID only: an expired lease that no other run has taken still accepts its run's writes and finish, because rejecting them would discard a nearly complete sync while no competing run exists. Completed data syncs restore `sourceUrl`, ETag and hash together; failures after writes cannot reuse validators from an earlier catalog. Removal uses the stored keys read before upserts. Before catalog writes, an unforced run that would make more than 20% of stored priced models unpriced finishes as partial with `partialReason: "price_loss"` without changing catalog rows. A run whose removal guard skips deletion finishes as partial with `partialReason: "removal"`. A partial run records its counters, which count the loaded catalog, and preserves the last completed timestamp. Malformed providers and models preserve their stored rows. Usable-provider and usable-model floors still apply; these floors also bound repeated removal across runs. Failed source attempts remain ordered fixed-message diagnostics, including when fallback succeeds.

`models.list` and `providers.list` return paginated documents. Provider pages use the provider-ID index, preventing accumulated 64 KiB provider rows from exceeding the query read limit. Cursors contain at most the selected index’s declared field count plus `_creationTime` and `_id`; shorter cursors remain valid prefix bounds. List pages require 1–100 items, read at most `numItems + 1` rows and target at most 1 MiB of document bytes. A document can reach or cross the byte target. Pinned intervals interrupted by those bounds return split metadata. Equivalent-model queries sort priced rows before unpriced rows, then by the required `costOrder` field in descending order. `costOrder` is negated blended price for priced rows and zero for unpriced rows.

Catalog requests are reads. Network failures, timeouts and HTTP 408, 429 or 5xx are retryable because repeating the read cannot create a second provider effect and the failure may be transient. Other HTTP failures are not retryable. Invalid or unexpected responses carry no retryable field.
